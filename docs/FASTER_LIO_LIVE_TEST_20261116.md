# Faster-LIO 在线性能测试记录（2026-11-16）

## 1. 测试范围与结论边界

用户允许使用已开启的雷达进行测试。本次只启动 MAVROS、MID360s 驱动、IMU 频率请求节点及独立 Faster-LIO；没有启动 EKF、PX4Ctrl、Diff-Planner 或 YOLO，没有解锁、切模式或发送航点。所有在线测试记录中的 FCU 均为 `connected=true, armed=false, mode=AUTO.LOITER`。

硬件是本机 Jetson Orin NX，功耗查询为 25W；Sunshine、ToDesk 与桌面进程仍运行。没有修改功耗模式、锁频或系统服务。原始 LiDAR 约 10 Hz，PX4 原始 IMU 实际约 170 Hz；200 Hz 是请求值，不是实际测量值。

**已复现定位地图点数不断增加导致的长期掉帧，不是仅凭配置推测。尚未完成完整飞行软件栈的负载验收，不能据此保证全开 10 Hz 或允许起飞。**

## 2. 如何测试

1. 先确认 ROS 中无已有 MAVROS、雷达、LIO 或控制器，再启动测试自己的节点；退出只停止测试创建的进程组。
2. 在线预热后采样输入及里程计频率、消息到达延迟、10 秒窗口、位姿变化与 FCU 状态，并记录 `tegrastats`。
3. 录下同一段输入包 `sensor_inputs.bag`：38.5 秒，385 条 LiDAR、6556 条原始 IMU，约 142 MiB。只包含传感器输入，不是飞行复盘包。
4. 每组同包测试启动新的 LIO，使用独立命名空间及 `/perf_replay/*` 输入、`/perf_test/*` 输出，不接入控制器。
5. 在线长测采样 300 秒；包含初始化和预热时节点存活更久。不能仅用启动后前 30 秒的 `rostopic hz` 判定通过。

包回放没有改变系统时间或开启 `/clock`。因此回放的“当前时间减历史时间戳”有很大的固定值，表格只比较同一次回放中前后窗口延迟的增长，不把这个固定值当作故障。

`last_frame_ms` 是完成同步后至该帧发布结束的单帧采样，不是平均值或 P95；IEKF 耗时是节点退出时打印的累计平均值，二者口径不同。

## 3. 只改粗采样还不够：5 分钟复现

配置为 `surf=0.30, map=0.50, point_filter_num=4, mapping/max_threads=3`，尚未限制每格地图点数：

| 指标 | 结果 |
|---|---|
| 300 秒里程计平均频率 | 8.408 Hz |
| 最后 10 秒里程计频率 | **5.462 Hz** |
| 前/后 10 条输出平均消息年龄 | 约 0.022 / **47.364 秒** |
| 地图点数，首/末性能采样 | 3984 → **980520** |
| 末次地图格数 | 3442 |
| 末次帧耗时 | 163.039 ms |
| 末次内部积压 | LiDAR 462 帧 / IMU 7903 条 |

注意：这次没有运行 YOLO、Planner 或 PX4Ctrl，已经能复现用户描述的约 5 Hz。因此不能将根因单独归咎于 YOLO 或远程桌面。

### 源码对应机制

- 默认 iVox 节点把同格点保存在 `std::vector`，原 `InsertPoint()` 每次直接追加；KNN 搜索遍历该格点列表。
- `MapIncremental()` 中选择靠近滤波格中心的新候选点，并不等价于删除旧的候选点。多次观测同一区域仍会持续积累点。
- `filter_size_map` 是入图选择尺度，不是“每格严格只有一个点”的上限；`map_grids` 很稳定也不能证明 `map_points` 没有膨胀。
- 原地图容量按格数限制，在本次只有几千格的情况下不足以阻止单格点数持续增长。

## 5. 每格限额策略：为何放弃循环替换

首次尝试每格最多 64 点、满后循环替换较早点。其 300 秒测试保持约 10 Hz，末次地图仅 109573 点、LiDAR 积压为 0，说明限制候选点可解决本次持续变慢的主要机制。

但同包回放的 Z 变化比未限额版本更大，在线 300 秒 Z 范围也达到 0.818 m。**不能为了频率通过就接受这种定位变化，该循环替换实现已从最终代码中移除。** 文件前缀 `bounded_*` 专指这个被放弃的中间版本，不代表最终修复。

后续策略为：格内未达到限额时正常插入；达到限额后保留最早进入的点、不再追加，避免持续用较新观测替换早期约束。默认点列表后端支持 `ivox_max_points_per_grid`；未设置或为 0 保持旧行为，负值拒绝初始化。PHC 后端未改动。

这仍是定位地图保留策略变化：已满的格无法接纳后来看到的新表面，可能影响动态场景、新视角及退化环境。64 是实验参数，不是已验证适合所有飞行场景的标准值。它不修改标定、时间偏移、TF 或发布扫描点云的密度，但改变定位结果仍会间接影响障碍地图位置。

## 6. 最终保留早期点版本的复测

同包复测的输出频率均接近 10 Hz，新实时档 Z 范围 0.166 m，未限额时为 0.174 m；与循环替换的 0.378 m 相比改善。但没有外部真值，这不等于精度认证，尤其不能把同包结果外推为带动力飞行稳定。

在线连续采样 300 秒，配置为 `.30/.50、取点 4、TBB 3、每格最多 64 点`，结果如下。两次在线长测不是同一次物理采样，环境或物体移动可能不同；同包对比见第 4 节。

| 指标 | 未限额长测 | 最终保留早期点版本 |
|---|---:|---:|
| LiDAR 输入频率 | 10.000 Hz | 10.000 Hz |
| IMU 输入频率 | 170.591 Hz | 170.559 Hz |
| 300 秒里程计平均频率 | 8.408 Hz | **10.000 Hz** |
| 最后 10 秒里程计频率 | 5.462 Hz | **10.009 Hz** |
| 最后 10 条输出平均年龄 | 47.364 s | **0.0221 s** |
| 全程输出年龄 P95 | 37.506 s | **0.0312 s** |
| 末次实际地图点数 | 980520 | **86649** |
| 末次地图格数 | 3442 | 3108 |
| 末次单帧耗时 | 163.039 ms | **19.794 ms** |
| IEKF 累计平均耗时 | 88.824 ms | 19.751 ms |
| 末次 LiDAR 内部积压 | 462 | **0** |
| Z 输出范围 | 0.268 m | 0.0540 m |

最终版本的 62 次性能采样中，LiDAR 内部积压均为 0，地图点数均满足 `map_points <= 64 * map_grids`。里程计消息的时间戳没有出现倒退或重复。本次位置输出 X/Y/Z 范围约 2.26 / 1.32 / 5.40 cm；这不是带外部真值的精度验收，也未覆盖手持、大角度旋转及飞行振动。

**本次“仅传感器 + Faster-LIO”的 5 分钟帧率/积压检查通过；完整任务栈及定位精度验收尚未完成。** 本次没有继续减小迭代次数、修改外参或放宽时间戳检查来换帧率。

1. 未解锁，按实际 EKF + PX4Ctrl + Diff-Planner + YOLO + Sunshine 组合运行至少 5～10 分钟，不能只启动本次传感器测试。
